# Shape exploration — not an approved direction

## Mechanism and scene

Proposed mechanism: a local-first HTTP workbench that preserves the short send/inspect loop while exposing the source and uses of values shared between requests. This is a design proposal, not an implemented capability.

Audience scene: an API power user moves among many saved requests, environments, and responses during extended desktop debugging sessions. Engineering notation, reference reading, and change review are the relevant cultural home.

The first surface must make the active environment, request, response state, and next action obvious. Category rut: dark three-pane client with a bright Send button; predictable opposite: oversized white cards and a simplified dashboard. Neither is a grounded visual direction by itself.

## Grounded systems, ordered by resonance

1. Engineering reference documentation: cool navy hierarchy, readable system type, precise cross-references; provenance notes in a conventional workbench.
2. Transit cartography publications: grouped route colors and disciplined labels; a compact dependency explanation beside a selected value, never a map replacing the editor.
3. Scientific figure conventions: low-noise surfaces, keyed semantic colors, exact annotations; response selection explains value origin in context.
4. Version-control diff traditions: restrained paired change colors and stable code alignment; compare current and previous response without losing scroll position.
5. Technical conference programs: compact schedules, confident section colors, clear humanist labels; execution history remains skimmable without dominating editing.
6. Package reference catalogs: dense readable indexes and stable identifiers; collections, tabs, and history preserve request identity.
7. Syntax-highlighting and technical annotation traditions: aubergine shell, lavender working ground, teal data and amber dependencies; selecting a response field exposes its source and uses in familiar inspector controls.

The systems span documentation/publication, cartography, scientific graphics, change notation, and event/index design. Operate mode limits their contribution to type, palette, density, and one signature interaction; navigation, pane layout, and controls remain conventional.
